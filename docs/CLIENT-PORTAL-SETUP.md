# Yehulu Digital client portal setup

The client portal is served at:

`https://yehulu-digital.vercel.app/client-portal`

It uses the same server-side session system as the existing administrator dashboard. The username is configured as `mihreteab`; the password is never stored in the public repository.

## 1. Connect storage

The portal needs persistent storage because Vercel Functions do not retain writes to the local project filesystem.

In the Vercel project **yehulu-digital**:

1. Keep the existing public Blob store `yehulu-digital-blob` for public portfolio media.
2. Create and connect a second Blob store named `yehulu-digital-private-cms` with **Private** access.
3. Use the `CMS_BLOB` environment-variable prefix when connecting the private store. Vercel creates `CMS_BLOB_STORE_ID` for the OIDC connection. The application uses this store ID with Vercel's short-lived OIDC authentication; a long-lived `CMS_BLOB_READ_WRITE_TOKEN` is not required.
4. The application also supports a manually configured `CMS_BLOB_READ_WRITE_TOKEN` for deployments that use a static read/write token instead of OIDC.

The private store persists administrator records, industries, sub-industries, organizations, and social profile links. It is used for dashboard data changes, not for accepting the admin login. The configured owner can still sign in when CMS storage is unavailable; saving CMS changes requires the private store to be connected. Never use the public media-store credentials for this private data.

## 2. Configure the initial login

Add these values to **Vercel → Project → Settings → Environment Variables**:

- `ADMIN_USERNAME` = `mihreteab`
- `ADMIN_PASSWORD_HASH` = a salted scrypt hash generated by `npm run admin:secrets` (Sensitive)
- `SESSION_SECRET` = the random session secret generated by `npm run admin:secrets` (Sensitive)

Apply them to Production and Preview. Do not put the plain-text password, password hash, session secret, or Blob credentials in GitHub.

For a fresh credential pair, run `npm run admin:secrets` from the repository root and enter a strong password when prompted. The script prints a hash and a random session secret; it does not print or save the password itself.

## 3. Deploy and sign in

Create a new Production deployment after adding or changing environment variables. Environment-variable changes do not update deployments that already exist. Then open `/client-portal`.

The portal workflow is:

1. Create an industry.
2. Add sub-industries inside that industry.
3. Create organizations under the industry and attach their website and social media profiles.
4. Upload portfolio images and assign each image to an industry, sub-industry, and organization.

Hosted image uploads are limited to 4 MB per image. Use optimized JPG, PNG, or WEBP images for the best upload experience.

## 4. Change the temporary password

The existing administrator account page at `/admin/account` supports changing the account password. Change the initial password to a unique password after first sign-in.

## Local development

For local development, add `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, and `SESSION_SECRET` to your untracked `.env` file. Local development can persist CMS records in `data/`. Never commit `.env` or any Blob credentials.


The private CMS connection can use Vercel OIDC when the store is connected with the `CMS_BLOB` environment-variable prefix. A new production deployment is required after changing administrator secrets.
